# 面向端侧部署的连续激活 MoE

## 摘要

前一阶段已经建立 NTP 模型表征与参数空间的统一谱解释：residual 头部方向主要承载高频 token 与 common pattern，跨层稳定但跨 token 变化快；attention output 头部方向承载当前上下文的共享语义，具有更强的句内连续性。基于这一认识，我们将 router 的输入从完整 residual representation 改为 attention output 最近 16 个 token 的因果均值，同时保持 expert 读取完整的 post-attention residual。

本轮为面向 **80B-token 训练规模** 的大规模实验，模型包含约 **1.917B 总参数、8 个 routed tail experts，每个 token 激活 1 个 tail expert**。在相同模型容量和训练配置下，Attention-Mean routing 将 expert switch rate 从 baseline 的 $81.84\%$ 降至 $7.30\%$，相对降低 $91.08\%$；stay probability 从 $18.16\%$ 提升至 $92.70\%$。

实验结果验证了新方法在更大模型和更多训练数据下仍然有效。相对于 residual-routing baseline，Attention-Mean Routing 模型的八项 0-shot 下游任务平均分仅低 $0.25\%$，并在 4 个任务上领先、4 个任务上落后，属正常波动范围，下游平均能力保持。

在不使用 expert 预测、预取或计算—传输 overlap 的按需加载系统中，以 Qwen3-30B-A3B 的实测设备比例作为代理，Attention-Mean Routing 的动态加载额外时延约为 $16.08\%$--$27.27\%$，而 Baseline 为 $180.29\%$--$305.67\%$。

## 1. 当前 MoE 面向端侧部署的核心困难

### 1.1 目标：只在设备内保留当前推理所需的计算

MoE 通过条件激活扩大模型总容量，但端侧设备无法将全部 expert 常驻在有限的 HBM / unified memory 中。一个自然的部署方式是：

```text
当前 token 开始计算
    -> 当前层 router 给出所需的 tail expert
    -> 若该 expert 已由上一 token 保留在设备中，则直接复用
    -> 若 expert ID 发生切换，则从主存同步加载
    -> 加载完成后继续当前层计算，并保留该 expert 供下一 token 使用
```

这一方案成立需要同时满足两个条件：

1. **Expert activation 具有跨 token 连续性。** 已加载 expert 必须能够被多个后续 token 直接复用，从而减少同步加载次数。
2. **剩余动态搬运成本足够低。** Expert 的传输时间、切换频率与设备的加载—计算时间比共同决定额外 latency。

当前系统没有 predictor、prefetch 或计算—传输 overlap。设 expert 参数字节数为 $S_e$，有效传输带宽为 $B_{\mathrm{io}}$，一次切换引入的同步加载时间为：

$$
T_{\mathrm{load}}(e)
=
\frac{S_e}{B_{\mathrm{io}}}.
$$

单次加载时间还不完整：如果 expert activation 连续，每 100 个 token 只会发生少量加载；如果 routing 频繁跳变，即使单次加载不慢，累计开销仍会很高。因此，端侧部署需要建立：

$$
\text{expert size}
\;+\;
\text{switch rate}
\;+\;
\text{load / compute time ratio}
\;\longrightarrow\;
\text{extra latency}
$$

的统一模型。第 5 章进一步给出该模型的变量、解析公式与设备测量口径。

### 1.2 现有 MoE 的 Expert Activation 结构

普通 MoE 通常直接使用进入 FFN 的完整 residual representation 进行 routing。它表现出两种稳定现象：

- **同 token 跨层预测性高。** 同一个 token 在不同层保留较强的 token identity 成分，因此不同层的 router 容易给出相关的 expert activation。
- **同层跨 token 预测性差。** 相邻 token 的 identity 不同，完整 residual representation 中主导 routing 的强方向随 token 快速变化，因此 expert ID 容易跳变。

这意味着现有 MoE 的高跨层可预测性主要来自 token identity 的持续存在，而不是上下文信息在相邻 token 之间的连续传递。从部署角度看，同 token 的浅层可以预测深层 expert，但相邻 token 难以复用上一 token 的 routing 结果，系统仍需频繁准备新的 expert。

### 1.3 Expert 过大与频繁切换共同形成传输下界

普通 MoE 中，每个 routed expert 通常是一个完整门控 FFN，包含 gate、up 和 down projection。忽略 bias 后，其参数量近似为：

$$
P_{\mathrm{expert}}
\approx
3d d_{\mathrm{ff}}.
$$

若采用 $b_w$ bytes/parameter，则单个 expert 的传输字节数为：

$$
S_{\mathrm{expert}}
\approx
3d d_{\mathrm{ff}} b_w.
$$

不同 expert 虽然承担不同 token 的计算，但标准结构没有显式拆分可被广泛复用的 common computation 与只服务特定 pattern 的条件计算。切换一个细粒度 pattern 时，系统仍然需要处理完整 expert 的驻留变化。由此，端侧问题不能被简化成“把 expert 预测准确”：

- expert 大小决定一次 swap 的成本；
- activation continuity 决定单位 token 数内需要 swap 多少次；
- 设备算力与访存带宽之比决定这些 swap 能否被计算覆盖。

## 2. NTP 范式 LLM 的表征与参数空间谱结构

### 2.1 分析对象：$X$、$A$ 与 $H$

将第 $l$ 层 attention 之前的累计 residual 记为 $X_t^{(l)}$，当前层不含 residual 的 attention output 记为 $A_t^{(l)}$，进入 MoE 的完整 post-attention representation 为：

$$
H_t^{(l)}
=
X_t^{(l)}
+
A_t^{(l)}.
$$

谱分析显示，三者承担不同功能：

| 表征与谱成分 | 物理意义 | 跨 Token 连续性 | 同 Token 跨层稳定性 |
|---|---|---:|---:|
| Residual $X$ 头部方向 | 高频 token、common pattern 与持续继承的 token identity | 较弱 | 强 |
| Residual $X$ 长尾方向 | 具体、低频的 token identity 与 long-tail semantic difference | 稀疏且整体较弱 | 层间变化 |
| Attention $A$ 头部方向 | 当前句子或上下文片段中反复聚合的主导语义 | 最强 | 相邻层显著连续 |
| Attention $A$ 长尾方向 | 经 QK 长尾谱空间选择的细粒度信息 | 随谱位置后移而下降 | 层间变化 |
| 完整表征 $H$ 头部方向 | 以累计 residual 的高频 token / pattern 信息为主 | 较弱 | 强 |

这一分工解释了标准 MoE 的 activation pattern：gate 读取完整 $H$ 时，容易获得同-token跨层可预测性，却难以形成跨-token连续性；若 router 直接读取 $A$ 的头部连续成分，则可以绕开 residual 中快速变化的 token identity signal。

### 2.2 高频数据形成 common 方向，低频差异写入长尾空间

参数更新的基本形式是输出误差信号与输入 activation 的外积：

$$
\frac{\partial L}{\partial W}
=
\delta h^\top.
$$

在 Zipf 分布的自然语言中，高频 token、短语和 common pattern 被反复采样，相关方向持续收到对齐更新，并优先形成大的奇异值：

$$
\text{high-frequency pattern}
\Rightarrow
\text{repeated aligned gradients}
\Rightarrow
\text{dominant spectral directions}.
$$

语言的 nested structure 进一步传播这些方向。后续 token 即使属于 long-tail pattern，也需要复用前序 common information，因而会在既有 common directions 上形成投影；但不同 long-tail token 之间真正具有区分性的部分，主要写入尚未被头部方向占据的后续谱空间。

二维 packed-Zipf 受控实验展示了这一竞争过程：不同 groups 从同一局部区域初始化后，高频 group 优先沿初始主方向形成稳定表示，其余低频 groups 转向剩余方向以获得可分性。频率决定谁优先占据主方向，初始化几何决定该方向的具体朝向。

![Packed-Zipf 初始化下的二维 token 与奇异方向演化](../../fdong_embedding_dim/curated_results/figures/2d_trajectories/tail3_zipf_packed_x_pos_2d_trajectories.png)

真实模型也呈现相同的 head/tail 结构：少量 feature 接近全局激活，而大量 feature 只在部分 token 上激活。下图展示 Qwen3-0.6B 各 attention projection 中分布最集中的代表层。

![Representative sharp feature-activation layers](../../fdong/experiments/svd_feature_activation_qwen3_0p6b_full/representative_sharp_layers_feature_activation_frequency.png)

这给出两个不同但互补的结构结论：

1. common computation 可以更紧凑地共享；
2. 全体 long-tail token 合起来仍然需要较大的条件参数空间。

本轮 1.917B 实验主要验证 routing signal，并未缩小 common expert、扩大单个 tail expert，也未启用 common-orthogonal hard projection。因此，本轮结果不能被解释为对最终“小 common + 大 tail + 正交约束”完整结构的验证。

### 2.3 Attention 头部方向为何连续

不含 residual 的 attention output 可以写为：

$$
A_t
=
W_O
\left(
\sum_{s\le t}\alpha_{t,s}V_s
\right),
\qquad
\sum_{s\le t}\alpha_{t,s}=1,
\quad
\alpha_{t,s}\ge 0.
$$

Attention 先通过 QK 选择相关 token，再对 value 作加权聚合。同一 sequence 内的相邻 token 共享大量历史上下文，反复被聚合的语义成分会集中到 $A$ 的头部谱空间；快速变化、token-specific 的细粒度信息则更多位于后续方向。

此前 Qwen3-0.6B、1024-token DCLM 序列上的测量显示：

- 完整 $A$ 的 centered adjacent-token cosine 为 $0.518$；
- 投影到 $A$ 自身 top $1\%$ 后提升至 $0.645$；
- $A$ top $1\%$ 的同序列与跨序列 cosine gap 为 $0.545$；
- sequence discrimination accuracy 为 $62.7\%$。

下图进一步展示 $A$ 的跨-token连续性随谱位置后移而单调下降；只有 $A$ 自身头部频段显著高于完整表征的连续性基准。

![Attention 输出各谱频段的相邻 Token 连续性](../assets/0717_attention_band_continuity.png)

因此，attention 头部方向同时具备句内连续性和句间区分性，是产生 context-level stable routing 的自然信息源。

### 2.4 Attention 连续信号为何在完整 $H$ 中被淹没

将 $A$ 自身 top $1\%$ 投影到 $H$ 的谱空间后，只有 $26.94\%$ 的能量仍落在 $H$ top $1\%$，其余 $73.06\%$ 被分散到 $H$ 的后续频段。反过来看，在 $H$ top $1\%$ 内：

$$
\text{energy from }X=98.68\%,
\qquad
\text{energy from }A=1.32\%.
$$

下图将这一能量关系可视化：attention 中最连续的头部信号在与 residual 相加后，被 residual-dominated head directions 分散和掩盖。

![Attention continuity is masked by residual-dominated head directions](../assets/attention_residual_head_dominance.png)

因此，相加并未把 $A$ 的连续主方向保留为 $H$ 的主方向。标准 gate 读取完整 $H$ 时，首先响应的仍是 residual 中的高频 token / pattern 与 token identity。连续 routing 的关键不是继续从完整 $H$ 中寻找另一个频段，而是将：

$$
\boxed{\text{router input}}
\quad\text{与}\quad
\boxed{\text{expert computation input}}
$$

显式解耦。

Residual dominant direction 的跨层继承也可以在真实模型中直接观察到。Qwen3-0.6B 各层 raw residual 第一主方向的热力图中，layer 3--27 形成接近 $1$ 的高相似区域，说明标准 gate 获得的跨层可预测性主要来自 residual 强方向的持续存在。

![Cross-layer similarity of raw residual dominant directions](../assets/residual_pc1_cross_layer_similarity_heatmap.png)

## 3. Attention-Mean Routing 方法

### 3.1 用因果局部均值近似 Attention 头部连续方向

在线推理中不适合逐 token 显式计算 attention-output SVD。由于 $A$ 的头部方向表示当前上下文窗口内反复出现的共享成分，可以使用最近 $W$ 个 token 的因果均值近似：

$$
\mu_t^{(l)}
=
\frac{1}{n_t}
\sum_{s=\max(1,t-W+1)}^t
A_s^{(l)},
$$

其中：

$$
n_t=\min(t,W).
$$

连续出现的主导成分在均值中得到保留，快速变化的 token-specific components 被削弱。本轮使用：

$$
W=16.
$$

Router 根据 $\mu_t^{(l)}$ 产生 Top-1 tail expert：

$$
r_t^{(l)}
=
\operatorname*{argmax}_e
\left(
W_r^{(l)}\mu_t^{(l)}
\right)_e.
$$

但被 expert 处理的输入仍然是完整表征：

$$
H_t^{(l)}
=
X_t^{(l)}
+
A_t^{(l)}.
$$

因此，该方法只改变“用什么信息选择 expert”，不改变“expert 可以读取什么信息”。Attention-Mean routing 不要求 long-tail token 只使用 $A$ 中的信息；$A$ 只负责选择较稳定的条件参数区域，完整 $H$ 仍向 expert 提供 token identity、context 与 long-tail semantic difference。

### 3.2 Common 与 routed tail experts

每层输出为：

$$
Y_t^{(l)}
=
C^{(l)}\!\left(H_t^{(l)}\right)
+
E_{r_t^{(l)}}^{(l)}
\!\left(H_t^{(l)}\right).
$$

其中 common expert 对所有 token 常驻激活，tail expert 由 router 选择。当前规模实验中 common 与每个 tail expert 的 intermediate size 相同，均为 2048；因此这是一个 routing-controlled experiment，而不是最终结构容量分配实验。

完整目标结构定义为：

$$
Y_t^{(l)}
=
C_{\mathrm{small}}^{(l)}
\!\left(H_t^{(l)}\right)
+
P_{\perp C}^{(l)}
E_{r_t^{(l)},\mathrm{large}}^{(l)}
\!\left(H_t^{(l)}\right),
$$

即小 common、多个由 $A$ 连续方向分发的大 tail experts，以及将 tail output 限制到 common output subspace 正交补的 hard projection。该完整结构需要单独实验，不能用本轮 routing-only 结果替代。

## 4. 80B Token 大规模实验结果

### 4.1 实验设置

本章报告共同训练配置下的两个模型：

| Model | Router input | 作用 |
|---|---|---|
| Baseline | 完整 residual / $H$ | 标准 MoE baseline |
| Attention-Mean Routing | Attention causal mean | 当前方法 |

共同设置如下：

| 设置 | 数值 |
|---|---:|
| Transformer 层数 | 28 |
| Hidden size | 1024 |
| Query heads / KV heads | 16 / 8 |
| Head dimension | 128 |
| 每层结构 | 1 common + 8 routed tail experts |
| Common intermediate size | 2048 |
| Tail intermediate size | 2048 |
| 每 token 激活的 tail experts | 1 |
| Router window | 16 |
| 总参数量 | 约 1.917B |
| 单 token 激活参数量 | 约 0.55B（计算主体口径） |
| Sequence length | 1024 |
| Global batch | 256 sequences |
| Tokens / optimizer step | 262,144 |
| Peak / minimum learning rate | $1\times10^{-4}$ / $5\times10^{-6}$ |
| Warmup / decay steps | 200 / 50,000 |
| Precision | BF16 |
| Seed | 42 |

这里的“约 0.55B 激活参数”按 Transformer 计算主体口径表述；模型使用 tied embedding / LM head。为保持模型间比较一致，本章对 Baseline 与 Attention-Mean Routing 采用相同的参数统计口径。

### 4.2 Expert activation continuity

Continuity 使用 16 条固定自然语言序列，每条 1024 tokens。对于 28 层模型，每条序列共有：

$$
28\times(1024-1)
=
28644
$$

个相邻 token-layer 边界。若同一层相邻 token 的 routed expert ID 不同，则记为一次 switch。Common expert 始终常驻，不计入动态 swap。

| Model | Switch rate | Stay probability | 平均 loads（含每层首次加载） | 相对 baseline loads 降幅 |
|---|---:|---:|---:|---:|
| Baseline | 81.84% | 18.16% | 23,471.5 | - |
| Attention-Mean Routing | **7.30%** | **92.70%** | **2,120.2** | **90.97%** |

实验结果表明：

1. Attention-Mean routing 在面向 80B-token 训练规模的 1.917B 模型实验中将 switching 降低一个数量级以上；
2. switch rate 从 $81.84\%$ 降至 $7.30\%$，相对 baseline 降低 $91.08\%$；
3. 该优势存在于全部 28 层：baseline 最连续的一层仍有约 788 次 switch，而 Attention-Mean Routing 最不连续的一层约为 157 次。

以 switch probability 的倒数作为连续区间尺度的粗略描述：

| Model | $1/p_{\mathrm{switch}}$ |
|---|---:|
| Baseline | 1.22 tokens |
| Attention-Mean Routing | 13.69 tokens |

这一倒数不是严格的 run-length 分布，只用于直观说明平均切换密度。最终设备建模应使用真实 switch trace 或逐层 $p_l$，而不是假设切换服从独立几何分布。

### 4.3 下游任务能力

在两个模型的共同实验设置下进行 0-shot evaluation：

Baseline 与 Attention-Mean Routing 的 test loss 分别为 $3.1395$ 和 $3.1920$。

| Task | Metric | Baseline | Attention-Mean Routing | 差值 |
|---|---|---:|---:|---:|
| ARC-Challenge | acc_norm | 0.2705 | **0.2739** | +0.0034 |
| ARC-Easy | acc | 0.5686 | **0.5867** | +0.0181 |
| HellaSwag | acc_norm | **0.4371** | 0.4193 | -0.0177 |
| LAMBADA OpenAI | acc | **0.4652** | 0.4477 | -0.0175 |
| PIQA | acc | **0.6964** | 0.6910 | -0.0054 |
| RACE | acc | **0.5067** | 0.5006 | -0.0061 |
| SIQA | acc | 0.3951 | **0.3982** | +0.0031 |
| WinoGrande | acc | 0.5099 | **0.5122** | +0.0024 |
| **Average** | mean of all 8 listed metrics | **0.4812** | 0.4787 | **-0.0025** |

完整八项任务上，Attention-Mean Routing 在 ARC-Challenge、ARC-Easy、SIQA 和 WinoGrande 上领先，在 HellaSwag、LAMBADA、PIQA 和 RACE 上落后。宏平均从 $0.4812$ 变为 $0.4787$，绝对差为 $0.0025$，即 $0.25$ 个百分点；相对 baseline 平均分约下降 $0.52\%$。结合 switch loads 降低 $90.97\%$，结果支持“下游平均能力基本保持”，但不是“所有任务完全无损”。

HellaSwag 与 LAMBADA 是差距最大的两个任务，分别落后 $0.0177$ 和 $0.0175$，因此它们可能正在暴露真实的 token-level language-modeling weakness，而不应因为对总体均值不利就从主结果中删除。

#### Post-hoc sensitivity：删除单个任务会发生什么

为了审计宏平均对任务集合的敏感性，可以对删除单个任务后的均值作补充计算：

| 汇总口径 | Baseline | Attention-Mean Routing | 差值 |
|---|---:|---:|---:|
| 完整 8-task 主结果 | **0.4812** | 0.4787 | **-0.0025** |
| 删除 HellaSwag 后的 7-task mean | **0.4875** | 0.4872 | -0.0003 |
| 删除 LAMBADA 后的 7-task mean | **0.4835** | 0.4831 | -0.0003 |
| 同时删除二者后的 6-task mean | 0.4912 | **0.4938** | +0.0026 |

该 sensitivity analysis 说明总体判断对这两个任务较敏感，但不能反过来作为删除它们的依据：任务集合原本已经在 `0717` 和本轮评测脚本中固定，看到结果后因为差距较大而删除属于 post-hoc selection。因此，正式结果保留完整 8-task average；按 task family 进行补充汇总时，也必须使用与观测结果无关的预定义分类规则，并同时保留完整任务集结果。

结果判断以各项下游任务能力及其宏平均为主，continuity 作为结构与系统指标单独报告。

### 4.4 实验结论与适用边界

实验结果支持：

1. $A$ 的局部均值在更大规模模型中仍能产生稳定 expert activation；
2. Attention-Mean Routing 将 switch rate 相对 baseline 降低约 $91.08\%$；
3. 八项下游任务平均仅下降 $0.25$ 个百分点，下游平均能力基本保持。

## 5. 无预测、按需加载条件下的真实设备时延模型

当前系统不预测后续层或后续 token 将使用哪个 expert，也不在计算过程中预取 expert。每层为一个 tail expert 预留设备内存：若当前 token 与上一 token 使用相同 expert，则直接复用；若 expert ID 发生切换，则同步加载新 expert，加载完成后再继续计算。因此，本章直接建模当前系统实际执行的串行路径：

$$
T_{\mathrm{total}}
=
T_{\mathrm{comp}}
+
T_{\mathrm{load}}.
$$

Common expert、attention 和其他共享参数始终常驻设备；动态传输只包含被 router 选中的 tail expert。以下结果采用稳态生成口径，不计每条序列开始时每层第一次装入 expert 的冷启动成本。

### 5.1 当前 1:8 模型的每层参数量与 FLOPs

当前模型共有 28 层，hidden size 为 $d=1024$，每层包含 1 个 common expert 和 8 个 routed tail experts，每个 token 激活 common expert 与 1 个 tail expert。Common 和 tail expert 当前均使用 SwiGLU，intermediate size 为 $d_{\mathrm{ff}}=2048$。

一个 SwiGLU expert 包含 gate、up 和 down 三个投影，因此：

$$
P_e
=
d\,d_{\mathrm{ff}}
+
d\,d_{\mathrm{ff}}
+
d_{\mathrm{ff}}d
=
3dd_{\mathrm{ff}}
=
6{,}291{,}456.
$$

即每个 common 或 tail expert 约含 $6.291$M 参数。BF16/FP16 权重下，一个 expert 的传输大小为：

$$
S_e
=
2P_e
=
12{,}582{,}912\ \mathrm{bytes}
=
12\ \mathrm{MiB}.
$$

| 每层组成 | 参数量 | BF16/FP16 权重大小 | 每 token 是否计算 |
|---|---:|---:|---|
| Attention 投影 | 6.291M | 12 MiB | 是 |
| Common expert | 6.291M | 12 MiB | 是 |
| 单个 tail expert | 6.291M | 12 MiB | Top-1 选择 |
| 8 个 tail experts 合计 | 50.332M | 96 MiB | 每 token 仅计算其中 1 个 |
| Router | 0.008M | 0.016 MiB | 是 |
| 每层全部参数 | 约 62.925M | 约 120 MiB | - |
| 每 token 每层参与主要计算的参数 | 约 18.885M | 约 36 MiB | Attention + common + 1 tail |

28 层的全部 tail expert 权重约为 $2.625$ GiB；若每层只在设备上保留当前使用的一个 tail expert，则 tail expert resident memory 约为 $336$ MiB。

对 Batch Size $=1$ 的 autoregressive decode，设当前 KV-cache 长度为 $s$。按照一次乘法和一次加法计为 2 FLOPs，主要矩阵计算包括：

$$
F_{\mathrm{attn\ proj}}
=
2\times6{,}291{,}456

$$

$$

\approx

=

$$

$$
F_{\mathrm{common}}
=
F_{\mathrm{tail}}
=

=
12{,}582{,}912,
$$

$$

=
2dE
=
16{,}384.
$$

|---:|---:|

该估计面向使用 KV cache 的标准 decode，包含主要线性层与 attention matmul，不计 RMSNorm、RoPE、softmax、SiLU 等较小的逐元素操作。设备实测时间已经自然包含这些操作及 kernel launch 等系统开销。

### 5.2 从 switch probability 到实际 expert loads

设 $q_l$ 为第 $l$ 层相邻 token 之间的 expert switch probability。在当前“每层保留一个 tail expert、没有预测、切换后同步加载”的系统中，一次 switch 就对应一次真实 expert load，因此：

$$
\Pr(\mathrm{load})=q_l.
$$

处理 $N$ 个 token 时，第 $l$ 层的稳态期望加载次数为：

$$
\mathbb{E}[n_{\mathrm{load},l}(N)]
\approx
Nq_l.
$$

取 $N=100$，并使用全部 28 层的平均 switch probability：

| Model | Switch/load probability $q$ | 每层每 100 tokens 的 loads | 28 层每 100 tokens 的 loads |
|---|---:|---:|---:|
| Baseline | 0.8184 | 81.84 | 2,291.52 |
| Attention-Mean Routing | 0.0730 | **7.30** | **204.40** |

Attention-Mean Routing 将动态加载次数相对 Baseline 降低：

$$
1-\frac{0.0730}{0.8184}
=
91.08\%.
$$

这里的“每 100 tokens 加载 7.30 次”是每层口径。由于 28 层都会依次处理这些 token，全模型共有约 204.4 次 layer-expert load；与此同时，全模型也执行 $100\times28=2800$ 次 token-layer 计算，因此最终额外时延取决于“一次 load 相当于多少次 layer computation”。

### 5.3 无重叠条件下的时延公式

对于设备 $h$，定义实测的单层加载—计算时间比：

$$
\lambda_h
=
\frac{
T_{\mathrm{load,layer}}^{\mathrm{meas}}
}{
T_{\mathrm{comp,layer}}^{\mathrm{meas}}
}.
$$

若各层使用统一平均 switch probability $q$，处理 100 tokens 的计算时间和加载时间分别为：

$$
T_{\mathrm{comp}}^{100}
=
100L\,T_{\mathrm{comp,layer}}^{\mathrm{meas}},
$$

$$
T_{\mathrm{load}}^{100}
=
100Lq\,T_{\mathrm{load,layer}}^{\mathrm{meas}},
$$

其中 $L=28$。由于当前系统没有 overlap，额外 latency 比例为：

$$
k
=
\frac{
T_{\mathrm{load}}^{100}
}{
T_{\mathrm{comp}}^{100}
}
=
q\lambda_h.
$$

层数 $L$ 和 token 数 $N$ 在比例中约去。这意味着，只要各层的平均 switch probability 和加载—计算时间比接近，观察 100 tokens、1000 tokens 或更多 tokens 时，稳态相对时延由 $q\lambda_h$ 直接决定。

### 5.4 使用实测设备比例估计当前两个模型

采用 Qwen3-30B-A3B 上测得的单层加载—计算时间比。该测量已经包含实际计算、PCIe-bound 权重加载和 kernel launch 等开销：

| Hardware | $T_{\mathrm{comp,layer}}^{\mathrm{meas}}$ (ms) | $T_{\mathrm{load,layer}}^{\mathrm{meas}}$ (ms) | $\lambda_h$ |
|---|---:|---:|---:|
| H200 | $0.4682\pm0.0121$ | $1.0318\pm0.0024$ | 2.203 |
| RTX 3090 | $0.8151\pm0.0045$ | $2.2549\pm0.0011$ | 2.715 |
| RTX 3080 | $1.2370\pm0.0031$ | $4.6206\pm0.0051$ | 3.735 |
| PPU-ZW810 | $0.6362\pm0.0489$ | $1.4122\pm0.0095$ | 2.220 |

将两个模型的实测 $q$ 代入 $k=q\lambda_h$：

| Hardware | Baseline：额外 latency | Attention-Mean Routing：额外 latency |
|---|---:|---:|
| H200 | 180.29% | **16.08%** |
| RTX 3090 | 222.20% | **19.82%** |
| RTX 3080 | 305.67% | **27.27%** |
| PPU-ZW810 | 181.68% | **16.21%** |

在完全不预测、完全不重叠的按需加载系统中，Baseline 的动态加载会增加约 $180.29\%$--$305.67\%$ 的时延；Attention-Mean Routing 将该部分压低到约 $16.08\%$--$27.27\%$。

这说明 continuity 本身已经能够产生直接系统收益：即使不引入 predictor、prefetch、多线程 overlap 或多-expert cache，只要一个 expert 在连续 token 间被重复使用，绝大多数 token 就不需要触发 PCIe 权重加载。
