# 基于滑动注意力聚合的确定性专家路由稳定性判定单元及执行方法

## 摘要

本方案利用 Attention-Mean Routing 的滑动窗口结构，维护注意力聚合变化量与上次路由分数裕量。硬件根据保守数学界判断当前输入是否仍由同一专家取得最高路由分数；判定成立时直接输出已确认的专家编号，未成立时执行完整路由计算。

方案目标是减少完整路由矩阵计算及后续配置更新，判断依据来自当前输入和已维护状态。它与三阶段算法的具体计算形式直接关联，适合具有大量专家或低功耗控制需求的专用推理硬件。

本文给出实数计算下的充分条件及有限精度实现要求。性能和判定通过率均待验证，尚无专利新颖性结论。

## 1. 问题动机与算法依据

项目采用长度为 16 的注意力输出因果窗口均值，经线性 router 选择 Top-1 专家。相邻 token 的专家身份经常保持一致，完整路由计算因此有机会通过稳定性证明而省略。

专家身份不变的统计概率与可低成本证明不变的概率是两件事：路由分数非常接近时，即使最终专家相同，保守判定也可能失败。首轮实验需要测量实际证明通过率。

## 2. 现有方案与相关工作

| 技术路线 | 已有能力 | 本方案拟研究的结合点 |
|---|---|---|
| 线性 router 与 Top-1 硬件 | 完整计算分数并选最大值 | 利用滑动输入变化判定最大值身份保持 |
| 增量线性计算 | 由输入增量更新输出 | 用更便宜的界检查省略完整增量矩阵计算 |
| 分支定界和提前终止 | 在充分条件下缩小搜索 | 保留路由裕量并跨 token 维护证据 |
| 专家连续性算法 | 减少实际专家切换 | 将连续性转成可证明的设备侧执行条件 |

已有 Top-k 硬件专利及增量推理技术需要重点比对。检索中出现的 US11188302B2 为 Top value computation on an integrated circuit device，可作为进一步检索入口。

## 3. 核心方案与数学条件

### 3.1 滑动更新

记当前层注意力输出为 $a_t$，窗口长度为 $W$。窗口填满后：

$$
\mu_t=\mu_{t-1}+\Delta_t,\qquad \Delta_t=(a_t-a_{t-W})/W.
$$

线性路由分数为 $z_e(t)=w_e^\top\mu_t+b_e$。专家仍读取完整 post-attention 激活。

### 3.2 由最近完整路由建立锚点

在时刻 $t_0$ 完整计算路由分数，记录胜出专家 $e_0$ 及其相对第二名的裕量：

$$
m_0=z_{e_0}(t_0)-\max_{j\ne e_0}z_j(t_0).
$$

对每个可能的胜出专家，离线计算保守常数：

$$
L_e=\max_{j\ne e}\|w_e-w_j\|_1.
$$

令当前均值相对锚点的累计位移为 $d_t=\mu_t-\mu_{t_0}$。若：

$$
m_0>L_{e_0}\|d_t\|_\infty,
$$

则所有其他专家仍低于 $e_0$，可确认当前 Top-1 身份不变。

关键在于比较相对最近完整路由时刻的累计变化。连续多次跳过完整计算时，不能一直用单步变化去对比最初裕量。

### 3.3 硬件结构

单元包括注意力窗口缓冲、均值更新单元、锚点或累计变化存储、绝对值最大归约电路、裕量比较器及完整 router 通路。

判定通过时输出专家号；失败时计算全部路由分数并建立新锚点。所有状态按请求和层隔离，模型更新时重新加载界常数并失效旧锚点。

### 3.4 有限精度与路由权重

要保持与目标数值实现一致，需要将均值累计、点积舍入和比较误差纳入保守余量 $\epsilon_t$：

$$
m_0>L_{e_0}\|d_t\|_\infty+\epsilon_t.
$$

误差界应针对实际数据类型、归约顺序和更新次数推导；无法保证时执行完整 router。分数相等时使用与基线一致的决胜规则。

当前判定只确认专家身份。如果模型输出还使用随 token 变化的门控系数，仍需按模型定义计算该系数。依赖全专家 softmax 的门控系数会限制可省略的计算量。首个实施例采用专家身份决定分支、无额外动态缩放的 Top-1 模型。

### 3.5 收紧判定界

全局常数过于保守时，可按向量分块计算变化上界，或分组保存竞争专家裕量。增加状态与检查成本可提高通过率，需以实际总耗时选择配置。

窗口尚未填满时采用正确的变长均值更新，或直接执行完整路由，待窗口填满后启用稳定性检查。

## 4. 四阶段实施例

1. **初始化。** 当前层完成完整 router，记录专家 3、分数裕量和注意力均值锚点。
2. **计算新变化。** 下一 token 得到注意力输出，移除窗口最早输出，更新均值与累计变化。
3. **判断稳定性。** 累计变化上界小于剩余裕量时确认专家 3；否则完整计算 router，并更新专家及锚点。
4. **执行专家。** 将当前完整激活交给确认的专家；驻留或通信控制器可据真实专家号复用已有执行状态。

## 5. 性能与容量估算

设完整路由耗时 $T_{router}$，稳定性检查耗时 $T_{bound}$，检查通过率为 $q$：

$$
T_{new,router}=T_{bound}+(1-q)T_{router}.
$$

收益条件为 $qT_{router}>T_{bound}$。示例假设 $T_{router}=1$ 微秒、$T_{bound}=0.15$ 微秒、$q=0.8$，则路由部分耗时为 0.35 微秒，降低 65%。若完整路由仅占一层时延的 2%，该节省对应整层约 1.3%，尚需加入状态维护成本。

以上为假设演算。$q$ 必须从真实路由分数和误差界测量，不能直接取专家保持率。

窗口存储按 $Wdb_a$ 字节计算，其中 $d$ 为维度、$b_a$ 为每个元素字节数。若已有算法维护窗口，可复用相应空间；新增锚点、累计变化及分组裕量仍需计入。

## 6. 拟保护的技术点

1. **滑动注意力聚合与路由稳定性判定的组合。** 利用窗口进入和退出项构成实际输入变化。
2. **锚点裕量与累计变化证据维护。** 允许连续多个 token 跳过完整路由，同时保持充分条件有效。
3. **带有限精度余量的硬件判断与回退。** 通过时输出已确认身份，失败时完整计算并重建锚点。
4. **判定结果与专家执行状态联动。** 将确认的真实专家号传递到权重槽位、计算或通信控制通路。

## 7. 专利价值与商业价值

- **系统/装置类价值：** 小型归约与比较单元可集成到 router 前端。
- **方法类价值：** 累计变化、锚点刷新及误差界共同构成可验证流程。
- **架构平台类价值：** 可扩展到满足线性打分条件的其他连续选择任务。
- **产品价值：** 降低路由计算能耗和控制延迟，特别适合专家数较多的模型。

## 8. 可发现性

模型编译产物中可能包含逐专家界常数，设备状态中可能存在分数裕量、累计位移和锚点刷新计数。硬件 trace 可显示部分 token 完整 router 未执行，但专家选择与完整计算一致。

通过逐步增大输入累计变化，可观察超过阈值后恢复完整路由。该证据应与固件、常数表和数值实现结合，区分一般缓存或近似路由。

## 9. 可规避性与上位保护建议

### 9.1 潜在可规避点

1. 使用不同范数、分块界或竞争专家分组。
2. 用逐步扣减裕量代替显式保存锚点向量。
3. 将窗口均值改为其他线性因果聚合。
4. 用软件或向量指令执行界检查。

### 9.2 对应上位保护建议

1. 保护当前分数变化的保守上界与竞争裕量的比较关系。
2. 覆盖自最近完整计算起有效的累计证据维护方法。
3. 以可计算增量的因果聚合定义可扩展实施例，并给出各自条件。
4. 同时描述执行方法及专用装置，明确检查结果与完整路由回退通路。

数学界本身及一般提前终止可能已有广泛现有技术，应重点核对上述组合与具体实现。

## 11. 待验证事项与立项判断

首先离线计算真实分数裕量、累计变化及判定通过率，再实现与目标数值格式一致的检查。对输入突变、长时间连续通过、平分及模型更新进行一致性验证。

该方向与算法数学结构结合最紧，适合先做轻量原型。若界过于保守或路由占总时延很低，优先作为控制器的从属实施例，而非独立主专利。
