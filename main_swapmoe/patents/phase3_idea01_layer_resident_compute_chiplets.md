# 面向连续专家激活的按层权重驻留计算芯粒架构及执行方法

## 摘要

本方案面向低并发自回归推理，将 Transformer 的若干层固定映射到计算芯粒，并为各层近期使用的专家保留独立的本地权重空间。相邻 token 使用相同专家时，计算芯粒直接复用该层已保留的权重；真实路由改变时，控制器更新对应专家槽位。算法产生的跨 token 专家连续性由此转化为跨层执行间隔仍有效的本地权重复用。

方案拟解决的关键问题是：专家虽然留在设备外部内存中，但共享计算阵列执行其他层后，其片上权重仍可能被覆盖。核心设计包含按层保留的权重空间、共享计算阵列、真实路由驱动的局部替换以及跨芯粒激活传输。

本文为技术构想，硬件收益采用条件模型，尚无本架构实测。相关技术部分沿用已有检索线索，未完成逐项权利要求比对。

## 1. 问题动机与算法依据

### 1.1 场景与痛点

个人设备、边缘服务器及低并发专用推理设备在逐 token 解码时，每层仅使用少量专家。若多个层轮流使用同一片上存储，下一 token 回到某层时，即使专家编号保持不变，也可能需要再次从外部内存读取权重。

本方案针对外部内存到计算侧本地存储的重复权重传输。能否节省该传输，取决于本地存储能否跨越其他层的执行保留权重。

### 1.2 三阶段算法提供的条件

Attention-Mean Routing 对最近若干 token 的注意力输出做因果聚合，以该信号选择专家；专家仍处理完整的 post-attention 表征。项目 M、L 模型的相邻 token 专家切换率分别为 5.48% 和 6.40%，相同专家因而可以连续执行多个 token。

该性质属于同一请求、同一层的时间局部性。不同请求可以选择不同专家，跨请求的合并工作集需要单独计算。项目数据证明了加载需求降低；它尚未证明权重能放入目标芯粒的本地存储。

## 2. 现有方案及相关工作

| 技术路线 | 已有能力 | 本方案需要进一步解决的部分 |
|---|---|---|
| GPU 的 HBM、L2、SM 局部存储 | 层次化缓存和高带宽供数 | 多层交替执行时，明确保留各层活动专家权重 |
| 权重驻留数据流 | 在计算过程中复用权重块 | 将驻留范围扩展到跨 token、跨层执行间隔 |
| 流水线并行 | 将不同层分配到不同设备 | 将层映射与活动专家本地保留、真实切换控制结合 |
| 3D 存内计算 MoE | 专家存储与计算单元的物理组织 | 本方案采用可共享的计算阵列和按层管理的本地权重空间 |

NVIDIA GH100 架构可作为通用 GPU 基线；已有 IBM 专利 US20240086682A1 是重点比对线索。区别应通过存储保留范围、路由更新条件、计算资源共享方式和实际数据路径逐项核对。

## 3. 核心方案

### 3.1 硬件结构

每个计算芯粒包含计算阵列、本地权重存储、层级驻留表和激活通信接口。大容量内存保存完整模型。按层驻留表记录模型版本、层号、专家号、物理槽位、有效状态及在途引用数。

每个芯粒负责一个或多个层。本地权重存储按层保留配额，某层暂未执行时，其配额内权重继续保留。计算阵列可在所负责的层及多个请求之间复用。

### 3.2 权重容量与物理实现

本地存储可以采用独立 SRAM、封装内专用存储或芯粒邻接存储。必须分别核算容量、面积、带宽和功耗；不同介质对应不同收益。

设芯粒负责层集合为 $G$，每层保留 $K_l$ 个专家，专家字节量为 $S_l$，则专家容量需求为：

$$
C_{expert}\geq\sum_{l\in G}K_lS_l.
$$

Attention、共享专家和计算缓冲另计。以项目 L 模型的 BF16 专家为例，单专家约为 $3\times1024\times2048\times2=12$ MiB；28 层各保留一个专家约需 336 MiB。该数字说明全量采用 SRAM 的成本必须认真评估。

### 3.3 真实路由驱动的更新

当前路由命中本地有效槽位时，直接发射计算。未命中时，选择无在途引用的槽位，从容量内存加载完整专家或按计算块加载，完成后更新映射。权重只读时无需将被替换专家写回。

按块实现需要保留足够的块集合；若所有块在每次前向后都被替换，跨 token 权重复用收益便无法成立。

### 3.4 多请求调度

请求按当前所需专家共享已有槽位。调度器可以在延迟预算内优先执行命中请求，并用年龄阈值保证其他请求得到服务。长序列 KV 状态保持其既定布局，跨芯粒传递当前激活及必要的请求标识。

## 4. 四阶段实施例

1. **执行当前层 Attention。** 对应芯粒读取当前激活和 KV，更新 KV，计算真实专家编号。
2. **查询本层权重。** 专家与本地记录一致时直接使用；变化时装入所需专家并更新记录。
3. **执行专家计算。** 共享阵列处理当前完整激活，输出送至下一层所在芯粒。本层权重继续保留。
4. **下一 token 复用。** 新 token 再次到达该层，路由相同则复用保留权重。请求结束或模型更新时释放、失效相应状态。

## 5. 技术效果与估算方法

设普通基线每次访问需从外部读取专家权重 $S$，本方案跨 token 本地保留后的实际未命中率为 $m$，则稳态专家外部读取量为：

$$
D_{base}=S,\qquad D_{new}=mS.
$$

在单请求、每层一个槽位、无额外淘汰条件下，$m$ 接近专家切换率。若取示例 $m=0.06$，专家外部读取量降低约 94%。这只对应专家权重读取，不代表整个模型时延降低 94%。

令 $T_{other}$ 包含相同计算和其他访存，$T_{link}$ 为新引入的层间传输及等待，则：

$$
T_{base}=T_{other}+S/B_{external},
$$

$$
T_{new}=T_{other}+mS/B_{external}+T_{local,extra}+T_{link}.
$$

需要检查：节省的外部供数时间是否覆盖新增本地访问与层间等待，以及低并发自回归执行下流水线是否空闲。多个请求能够填充流水线，同时会扩大专家工作集。

## 6. 拟保护的技术点

1. **按层保留的专家权重空间。** 层映射、本地容量配额及驻留表共同保证活动权重跨其他层执行仍有效。
2. **真实路由与本地权重更新联动。** 依据当前专家编号决定复用或加载，并以引用计数保证替换安全。
3. **权重保留与计算阵列共享。** 存储按层保留，计算资源可跨层和请求调度。
4. **激活流与局部更新协同。** 层间发送激活，权重变更限于发生真实切换的层及槽位。

## 7. 专利价值与商业价值

- **系统/装置类价值：** 形成计算芯粒、本地权重空间、容量内存和互连的明确组合。
- **方法类价值：** 形成路由确认、驻留查询、权重更新及计算发射的执行顺序。
- **架构平台类价值：** 同一机制可用于不同本地存储介质和芯粒数量。
- **产品价值：** 用本地存储资源换取外部带宽及能耗节省，适合连续解码专用产品。

## 8. 可发现性

公开架构资料可能出现按层容量配额、长期保留专家槽位和芯粒层映射。驱动中的层分配接口、驻留表和专家加载计数器可提供进一步证据。

黑盒测试可比较相同专家连续执行与强制切换时的外部权重读取量。还需观察其他层执行后本层权重是否仍保留；单纯命中缓存不足以识别完整方案。

## 9. 可规避性与上位保护建议

### 9.1 潜在可规避点

1. 将按层保留空间实现为可配置缓存分区。
2. 以专家块或压缩片段作为驻留单位。
3. 动态迁移层映射，采用单芯片分区替代多个芯粒。
4. 将驻留控制放在固件或编译运行时。

### 9.2 对应上位保护建议

1. 描述跨层执行间隔保持有效的容量与映射约束，覆盖不同存储名称。
2. 覆盖完整专家及可独立执行的权重分片，并说明所需保留集合。
3. 以计算域和层映射定义机制，具体芯粒封装作为实施形态。
4. 保护真实路由、保留状态和计算发射的协同行为，同时保留硬件装置限定。

上述为拟补充范围，授权范围需结合现有技术和权利要求文本确定。

## 11. 待验证事项与立项判断

优先验证本地存储面积、逐层真实权重保留率、低并发计算利用率和跨芯粒激活开销。该方向硬件变化明确，资源成本也最高。首轮应构建容量与层映射模拟器，确认外部访存节省足以覆盖新增硬件及通信成本。
