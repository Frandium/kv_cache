# 本发明技术方案（草稿）

本发明提出一种面向端侧 MoE 解码的「非对称分层存储 + 候选驱动预激活」的软硬件协同加速器架构。其核心思想是在同一加速器内配置小容量高带宽层与大容量低成本层，两类存储共同向同一个共享计算阵列供数；并利用连续性增强路由自身产生的跨 token 时间局部性与下一 token 可预测性，把「哪些参数值得占用高速容量」和「哪些参数需要提前多久开始准备」这两个原本只能由通用缓存策略事后猜测的问题，转化为可由路由信号直接驱动的确定性决策。该架构包含两个子模块：**子模块一「非对称分层存储与 Expert-Object 对象化寻址」解决容量维度的问题，子模块二「连续路由预测驱动的候选 Expert 分级预激活」解决时间维度的问题。** 该方案不依赖对 expert 热度的离线统计与事后修正，也不需要等待容量层 miss 发生后才被动响应，而是在路由结果产生之前即由算法信号完成容量分配与介质预操作的决策，从源头消除容量层带宽对端到端解码时延的影响。

## 子模块一：非对称分层存储与 Expert-Object 对象化寻址（容量维度）

### 如何工作

加速器内配置两类存储，二者通过各自控制器和互连向同一个共享计算阵列供数，不与特定计算核心绑定：

1. **高带宽层（fast tier）**：容量较小、聚合带宽较高，保存 working set——全部 attention/dense 权重与 router、输出 LM head、历史 KV Cache、每层有限数量的近期激活 expert slots，以及当前 token、hidden state、query、路由结果等小状态和必要的量化 scale 与元数据；
2. **容量层（capacity tier）**：容量较大、单位容量成本低、聚合带宽较低，保存当前未激活的 expert，即 idle set；
3. **层间复制/迁移引擎**：按 expert object、权重页或 KV page 在两类存储之间传输数据。

容量层不按通用虚拟页理解模型，而是把 expert 权重作为**只读的 expert object** 暴露给驱动，由 `(layer_id, expert_id)` 直接寻址：同一层内等尺寸的 expert，物理地址由固定步长公式

$$\operatorname{addr}(l,e) = \operatorname{layer\_base}(l) + e\,S_l$$

直接计算；变长或压缩的 expert，则由每层的 expert descriptor table 返回起始地址、长度、量化格式、校验信息与介质位置。驱动以**完整 expert** 为逻辑单位执行 `EXPERT_QUERY`、`EXPERT_READ`、`EXPERT_PROMOTE`、`EXPERT_COMMIT`、`EXPERT_RELEASE` 等对象命令，控制器负责把一个逻辑对象请求转换为底层连续突发、跨 channel 条带化或 Flash page read。

当前路由结果产生后，`(layer_id, expert_id)` 被直接转换为对象查询：命中高速层时由高速层向计算阵列供数；命中容量层时由 object controller 流式读取该 expert，可直接送入计算阵列，或在后续 token 需要持续复用时迁入高速层。

### 为何可以这么工作

**其一，容量—流量不对称由算法创造，而不是由静态冷热决定。** 标准 MoE 只具有「每个 token 只激活少量 expert」的瞬时稀疏性，相邻 token 的 expert 身份频繁切换，因此瞬时 active set 并不能被小容量高速存储长期承载。本项目的 Attention-Mean Routing 将相邻 token 的 expert stay probability 提高至 **92.70%**，使近期激活 expert 能够跨 token 持续复用，从而把瞬时稀疏性转化为**跨 token 的时间局部性**，形成可驻留的 working set。将该实测驻留率作为条件输入、代入公开 30B-A3B 同规模结构参照模型后，约 **16.4%–20.1%** 的运行容量即可覆盖约 **95.49%–96.95%** 的当前读取字节，容量层只需承担约 **3.05%–4.51%** 的运行时流量。

这一步是整个方案成立的因果前提：正因为流量如此集中，才敢于把高速层容量压到总运行容量的 **10%–40%**（优选 20%–30%），只为这一小部分容量支付高带宽成本；也正因为容量层只承担约 3%–4.5% 的字节，其较低的带宽才不会传导为端到端瓶颈。需要强调的是，上述比例描述的是**动态 working set** 的容量—字节覆盖关系，高速层内的具体 expert 身份随上下文变化，并不表示长期固定的少数 expert 永久热门。

**其二，容量层内容受限，使对象化寻址成立。** 容量层主要保存的是形状在模型加载时即已确定、推理期间只读的 inactive expert 权重。只读意味着不需要维护通用可写缓存所需的 dirty state 与写回路径；形状已知且层内通常等尺寸，意味着地址可以直接由 `(layer_id, expert_id)` 计算得出，而不必在运行时把每个 expert 拆成通用缓存页去做放置与替换。这使一个逻辑 expert-object 请求能够被控制器整体优化为长突发读取、跨通道条带化或 Flash 页合并，而不是退化为若干彼此无关的随机页访问。

## 子模块二：连续路由预测驱动的候选 Expert 分级预激活（时间维度）

### 如何工作

**步骤 1 · 产生候选集合。** 在当前 token 的计算期间，Attention-Mean Routing 对最近若干 token 的 attention output 做因果聚合，再经同一 router 得到下一 token 的候选 expert 集合

$$\mathcal{P}_{t+1}^{(l)} = \{(e_1,p_1),(e_2,p_2),\ldots,(e_K,p_K)\},\qquad p_1\ge p_2\ge\cdots\ge p_K .$$

**步骤 2 · 按置信度分级预激活。** 驱动根据候选等级、当前驻留状态、可用带宽与 staging 容量，选择不同强度的预激活动作：

| 候选等级 | 预激活动作 | 代价 |
|---|---|---|
| 已驻留候选 | 保持对应高速 slot 的有效期，避免被其他迁移请求替换 | 仅元数据 |
| 高置信度未驻留候选 | 发起完整 `EXPERT_PROMOTE`，预取整个 expert object 至高速层或 staging slot | 完整 expert 字节 |
| 中等置信度候选 | 仅激活对应 DRAM bank/row，或预读 expert object 的首个连续块、描述符与量化元数据 | 开行 / 首段 |
| 低置信度候选 | 仅在容量控制器请求队列中登记对象地址 | 不消耗数据带宽 |

不同物理介质对应不同的预激活实现：容量层为 DDR/LPDDR 时使用 bank/row 预激活与首段突发读取；为 Flash/UFS/NVMe 时将候选 expert 的一个或多个 page 读入 DRAM/SRAM staging；为多通道 DRAM 时提前配置 channel striping 与 DMA descriptor。

**步骤 3 · 真实路由产生后闭环。** 下一 token 的真实 router 结果产生后：

- 候选命中且完整权重已到达 → 控制器直接提交对应高速 slot，立即开始计算；
- 候选命中但只完成部分预读 → 继续传输剩余 expert object；
- 候选未命中 → 取消尚未发出的候选请求，并按真实 `(layer_id, expert_id)` 重新发起读取；已读入但未命中的候选数据可根据空闲高速容量保留或直接释放。

控制器同时统计正确预读与误读字节，在满足预读带宽预算

$$D_{\text{pre}} = S_e\sum_{i=1}^{K} q_i \le D_{\text{budget}}$$

的条件下，优先提高高置信度候选的预读比例 $q_i$。

### 为何可以这么工作

**其一，预测本身携带信息量，且直接来自算法自身状态。** 提高跨 token 连续性的同一个路由信号，同时也提高了下一 token expert 集合的可预测性——项目实测 **Recall@1 约 52%、Recall@4 约 86%–87%**。因此这里的预激活不是与路由无关的外部启发式猜测（如按历史访问频率、按层序号、按固定顺序预取），而是直接复用算法已经产生并在持续更新的状态，候选集合的质量随算法本身同步提升，这是通用缓存预取器无法获得的先验。

**其二，预测错误不产生正确性问题，只发生性能退化。** 真实路由结果始终是唯一决定：预读只负责提前准备，不参与 expert 选择；预测错误仅退化为一次普通的容量层读取，取消—重读路径保证计算结果完全等价。这使得方案可以在「更激进地提前」与「更保守地节省带宽」之间按置信度自由调节，而不必为保证正确性而牺牲预取深度。

**其三，预激活深度分级使误取代价与命中收益解耦。** 由于多数候选只需付出开行或首段预读的极小代价，即可消除容量层访问中最主要的启动时延，而完整复制只留给高置信度候选，因此总预读字节可由预算显式约束，误取带宽不会随候选数量线性增长。

## 附图说明：传统架构与本方案对比

**传统架构（左图）**：为共享计算阵列配置单一等级的内存。端侧方案采用片上 SRAM/TCM 与大容量 DDR/LPDDR 的组合，每个 token 的全部权重读取——包括 attention、历史 KV 以及被选中的全部 expert——均经由同一低带宽接口供数，batch-1 解码速度直接受限于完整模型的流式读取；若改用全容量高带宽存储，则大量当前未激活的 expert 也需占用昂贵的高速容量，介质、控制器与封装成本随模型总参数量线性增长。部分改进方案引入 hot expert buffer 或 tiered memory，但其放置与预取由通用缓存策略或静态频率统计驱动，与路由算法本身没有耦合，因此既无法确知高速容量应当配置多大，也无法在 miss 发生前主动发起介质操作。

**本专利架构（右图）**：存储被拆分为小容量高速层与大容量低速层，两类存储均向同一个共享计算阵列供数，而非各自绑定少量计算核心。高速层的容量与内容由连续路由所形成的动态 working set 决定——约占总运行容量的 10%–40%，却承载约 95%–97% 的读取字节；容量层不再按虚拟页逐页理解模型，而是按 `(layer_id, expert_id)` 把只读 expert 组织为可独立寻址的数据对象，等尺寸 expert 以固定步长公式直接生成物理地址。与此同时，在当前 token 的计算期间即由连续路由状态产生下一 token 的候选 expert 集合，驱动据此按置信度对容量介质执行驻留保持、bank/row 预激活、首块预读或完整预取，并在真实路由结果产生后提交、续传或取消。由此把容量分配与读取时机两个维度同时交由算法信号驱动，在 30B-A3B 同规模条件外推下，以约 20% 的高速容量与约 40% 的内存子系统成本增量，换取相对全 273 GB/s 容量型内存端侧基线约 **2.95–3.04 倍**的端到端解码加速，相对全 1.5 TB/s 高速存储则降低约 **53.3%** 的内存子系统成本，吞吐损失约 **6.4%–9.2%**。
